# HIC repository audit — 2026-10-28

Scope: `empire1-cloud/hybrid-intelligence-core-`, branch `main` at `b82efae`.
Method: findings come from reading and **running** the code — the live
`app.routes` table, the test suite, and targeted reproductions. Docs, ADRs, PRDs,
README and this repo's own `CLAUDE.md` were treated as claims to check, not as
evidence. Where a doc disagreed with the code, the code won and the doc was
corrected.

## Evidence tiers used below

| Tier | Meaning |
|---|---|
| **Tested** | A test in this branch fails on the original code and passes on the fix (mutation-checked for the ones marked ✓✓). |
| **Code-verified** | Confirmed by reading the code path end to end and/or inspecting the live route table; no automated test. |
| **Not verified** | Requires something not available in this audit (live MongoDB, provider keys, Stripe test mode, a deployed host). |

## Baseline (before changes)

- 28 backend test files. 10 run offline and passed (102 tests). **18 are
  live-server integration tests** (`requests` against `BASE_URL`) that need a
  running backend + MongoDB; CI runs **none** of them and CI ran only 3 of the 10
  offline files.
- App imports and starts route registration cleanly (`test_app_contract.py`).

## Not fixed — stated, not hidden

- **Git history still contains the key (C1).** Rotation is the fix; rewriting public history is the owner's call.
- **The 18 live-server test files were not run.** They need a real MongoDB and a running backend. Starting a downloaded `mongod` binary was blocked in this environment. The e2e suite covers the core journey with in-memory Mongo instead — real Mongo, index creation and the app lifespan are **not verified**.
- **No real provider call was made.** Engine output quality and provider credentials are **not verified**.
- **Stripe test-mode flow** (checkout → webhook → plan change → cancel) is **not verified** live; logic is unit-tested with a stubbed signature check.
- **Per-process state under 4 gunicorn workers:** rate limits (up to 4× the configured ceiling), the drift monitor (in-memory, fixed baselines — not a durable drift system), the process-local JSON execution log behind the public `/api/analytics/*` dashboard (aggregates all tenants; no prompt text exposed).
- **DNS rebinding** can still defeat the SSRF check (documented in `core/url_safety.py`).
- `POST /api/status` and `POST /api/empire1/analytics/event` remain anonymous, unbounded writes (low impact, left as product behaviour).
- `POST /api/route` (routing decision only, no model call) consumes an execution because it shares the Strategy router's billing dependency.
- 11 of ~19 engines are still not reachable from either orchestrator (`/core`, `/canon`); `HybridIntelligenceCore.ENGINE_MAP` is still unused.
- `requirements.txt` pins `google-genai` / `google-generativeai` etc.; no HIC code or the vendored client imports them directly (likely transitive for `litellm`). Removing them was not attempted because a full clean install could not be run here.
- **HIC / SLA113 repository boundary** (README says pure HIC; `main` ships SLA113 backend, standalone app and game artifacts) is documented, not restructured — per canon, separation should be additive and owner-directed.
- Stale `"gemini-3-flash"` entries remain in engine `MODEL_CONFIG` dicts. They are now inert (the resolver refuses any Google provider pair) and were left per "never delete".

## New configuration (see `deployment/env.production.template`)

| Variable | Purpose |
|---|---|
| `APP_ENV=production` | Enables fail-closed startup checks. |
| `JWT_SECRET_KEY` | Required in production, ≥ 32 chars. |
| `CORS_ORIGINS` | Explicit frontend origin(s). |
| `STRIPE_WEBHOOK_SECRET` | Required for webhooks to be accepted. |
| `SLA113_OPERATOR_KEY` | ≥ 24 chars; entered once in the SLA113 console. |
| `SLA113_AUTH_MODE` | `enforce` (default) or `audit` for a staged rollout. |
| `SLA113_GEMINI_IMAGE_EXCEPTION` | Off by default; `enabled` records a policy exception for the Gemini image route. |
